# Use Sunstack

Evidence before judgment: an authored standard or supplied taxonomy determines what source evidence means, and an operation's actual status limits the claim. Acquisition can itself ask a model when selection is configured, so execution authority and budget apply before acquisition. Restored SDK values preserve original data, including any status and provenance their root carries; decoding neither executes nor authenticates them.

1. Name the requested artifact and claim. Choose inspection for source pieces and locations, evaluation for decisions against an authored standard, or the SDK codec for saved typed data. For repository work, identify the checked root and scope; for classification, identify who supplied its policy.
2. Inspect configured selections and questions before acquisition. Apply the conversation's existing execution authority and budget; an ambient credential is availability, not permission. IF a required paid effect is uncovered by that authority, follow the host's existing permission policy and continue the relevant keyless work.
3. Read the interface that matches the selected route and installation before authoring:
   - IF using the CLI, load [the CLI guide](../../../crates/sunstack/README.md) and read the available tool's `sunstack --version` and `sunstack lint --help`; return the supported command, complete configuration dependencies and output interpretation. Installed help owns callable syntax. Apply repository guidance when the tool's release matches the workspace `Cargo.toml` version or the tool being used is a task-authorized build from this checkout.
   - IF writing a typed program, load the README and selected example from the resolved installed `@sunstack/sdk` package; return the complete typed values, strict compile command and outcome handling. Use [the repository SDK manual](../../../packages/sdk/README.md) when that installed package's `package.json` version and `contractInfo()` release/revision match checkout `packages/sdk/package.json` and generated `packages/sdk/src/contracts/contract-revision.ts`, or when the package being used is a task-authorized build from this checkout. An unversioned guide alone establishes no release identity; version matching does not verify binary bytes.
   - IF a tool or operation is missing or versions differ, report the dependency, both verifiable versions and unavailable flag or export, then use matching guidance or a task-supplied binary/package. Do not invent exports or install a replacement to make the recipe fit.
   - IF a missing tool needs a checkout build covered by existing task scope and host permissions, load the [root README build quickstart](../../../README.md) and [AGENTS.md Rust instructions](../../../AGENTS.md#rust), follow their documented procedure including the code-signing runner, and return the build result and its effects. A read-only task or uncovered build leaves the dependency unresolved.
4. For a typed program, author complete SDK values against the exported Rust-derived types with `satisfies`, literal unions and `as const` where narrowing is needed. For evaluation, admit definitions and proceed only on valid admission. Direct SDK inspection performs its own admission and can use an empty rulebook collection; handle its outcome without loosening ordinary evaluation admission. Strictly compile typed programs. Immediately before acquisition or execution, inspect the actual authored or edited selections and questions against the conversation's existing authority and budget again; use CLI `--check`'s listing where relevant and inspect typed definitions for SDK work, since SDK `check()` returns an admission summary. Apply step 2 to any uncovered paid effect, then run the actual SDK program or CLI command only within that authority.
5. IF saving or restoring known SDK values, follow the selected SDK manual's `serialize`/`deserialize` recipe and return the saved artifact plus the narrowed restored root, retaining any status and provenance it carries. Narrow both outcome and payload tags, leave file storage to the caller, and admit a restored configuration before evaluation. Use the owning codec instead of recreating numeric conversion; a decoded report is original data, not a new or authenticated check.
6. Deliver the requested artifact with the actual command, tool/package identity and result. For a typed program, include both strict compile and real run results; for CLI work, include the real command result. Report the actual outcome/status, selected scope, file and piece counts, relevant source locations and incomplete reasons. Keep extracted facts separate from policy judgments, and retain uncertainty, failure and zero or partial coverage in the conclusion. A clean listing means evidence work completed; it does not establish absence of violations.

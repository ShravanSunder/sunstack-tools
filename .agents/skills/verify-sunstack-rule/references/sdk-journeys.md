### Native HTML units at the 0.13 baseline

Read `html-sections.md` and the main native owners before qualifying new SDK declarations. `HtmlUnitSelection::Unit { units, filter }` is the Rust domain enum, not its Serde wire. The wire is `{mode: 'unit', units: ['section']}` with either no filter, `starts_with`, or `pattern`; those filter keys are mutually exclusive. A generated `{Unit: {units, filter}}` alternative is not the accepted wire. Compare the actual generated SDK input/result graph with `html_selection_contracts.rs::SelectionWire` and the Serde acceptance/refusal tests; do not hand-author another TS policy to compensate for an incorrect export.

An evidence kind owns exactly one of `rule`, `inline_rule`, or `html_units`. Its native outline form is:

```json
{
  "html_units": { "mode": "unit", "units": ["section"] },
  "fields": {
    "full": { "from": "section", "text": "full" },
    "own": { "from": "section", "text": "own" },
    "parent": { "from": "section", "text": "enclosing_own" }
  }
}
```

`select` keeps its model-selection meaning. The low-level `EvidenceSelection` wire uses the same flat selector with its tag: `{kind: 'html_units', mode: 'unit', units: ['section']}`. Native HTML kinds have no AST rule ID; `KindMatcher::ast_rule_id` returns None, so a synthetic AST identity is not an acceptable bridge. Empty units, unsupported modes/units, invalid or empty-matching patterns, conflicting filter/matcher keys and section fields on non-outline kinds must retain Rust-owned refusals. Intended compiler negatives must reject mutually exclusive new wire keys after an actual positive caller compiles.

Section ownership is lexical h1–h6 order, not DOM wrappers. Full keeps the whole section range; own excludes child sections; enclosing_own is the direct enclosing section's own range. Top-level enclosing_own is raw Absent and normal null asking input, not an unavailable/incomplete failure. Original bytes, source-relative spans and raw fields remain decisive. The frozen independent outlines/recovery cases in the HTML-sections route must not be regenerated from engine output.

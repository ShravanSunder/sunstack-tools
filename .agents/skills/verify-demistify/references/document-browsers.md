# Public document browsers

This journey checks a reader assembled from the public Demistify package: a need with its stages, related documents and call stack, including an independently prepared HTML collection. Its expected behavior is the reviewed [Requirements U1–U4](../../../../docs/specs/2026-11-07-design-documents/requirements.html), [Specification R1–R10](../../../../docs/specs/2026-11-07-design-documents/specification.html), [Program Design](../../../../docs/specs/2026-11-07-design-documents/program-design.html) and [Verification Design](../../../../docs/specs/2026-11-07-design-documents/verification-design.html). The wrapper is operable for the assertions in its permanent built-fixture files. Full source fidelity, scroller reachability, native interaction, first-author work, release and complete process cleanup require separate evidence; no product acceptance follows from this recipe.

## Target and readiness

Record the declared source commit, allowed dirty state, complete library and PoC build identities, fixture/source hashes, client, selected widths and themes. Before using prior before-state evidence, read its source/build/fixture identities, exact actions and assertions; reuse only what still matches. The selected comparison needs actual baseline pixels and metrics, not just an archive of baseline bytes. Do not build, install or start a browser without the current assignment's authority.

From the repository root, after a complete matching build is declared, run:

```sh
node apps/demistify-poc/scripts/verify-design-documents.ts --help
node apps/demistify-poc/scripts/verify-design-documents.ts
```

The wrapper selects the permanent `document-browsers`, `collection-entry`, `drawer` and `choices-comments` browser files through the existing Vitest built-fixture harness. The harness snapshots the built library and PoC consumer, starts an owned loopback service and awaits document/navigation, stylesheet, fonts and each case's own target. A responding port alone is not readiness. Read the current files and their assertions at the frozen target: selected file names, a green command or a screenshot alone do not establish every obligation below. Preserve the actual selected pass/fail/skip counts, raw output, snapshot and asset hashes, screenshots and metrics under the harness evidence root printed by `--help`. Confirm its owned browser and server stop; leave other processes alone.

## Source, preparation and reader

1. Fix an independent public-safe collection and its expected record IDs, owner pages, ordered relationships and rich body facts before seeing a candidate. Prepare it through the actual public CLI and checker, then load the actual public runtime/theme/chunks without the app bundle or fixture fallback. Capture the request/module graph as well as authored and prepared sources. Compare every supplied record, body, edge and semantic inline link/code/Markdown/diagram to the independent input; a global text search or copied expected output does not establish ownership. Keep a no-app-bundle negative control and the full selected lab inventory separately.
2. For needs-only, needs+rules, +design and +checks, and complete zero-stack collections, prepare and read the actual pages. Missing later stages say **Not yet written** and an empty call collection says no call paths are supplied. A separately authored broken or wrong-kind edge must fail, rather than becoming an unwritten stage. Preserve earlier outputs byte-for-byte after each invalid CLI input. Repeat preparation to check one carrier and stable unchanged output; check extra home/plan HTML stays authored.
3. Pin the selected S2 rule from its original conditions before the implementation's selector. A trailing note stays a note and cannot become the compact rule. Exercise absent, duplicate, unknown and wrong-kind explicit parts. Project rich bodies twice and check each local ID, fragment href, `for` and multi-token ARIA reference points to its own intended target; external links stay external. Read inline Markdown and actual Mermaid labels in the built reader as well as the preserved source.
4. On each browser page, change an out-of-root record body or relationship and re-prepare: its Comments revision changes. An unchanged prepare/reload keeps the same revision. Perform two local Markdown edit → prepare → load rounds, confirming the authored `src` remains intact and each edit changes the actual revision. With unprepared and invalid/version-mismatched carriers, the reader shows a diagnostic while Comments opens and resolves its source; no unregistered-source error. A pure hash-function test does not prove registration timing.
5. Drive the actual selected need, four views, related documents and contextual/standalone calls. Check correct visible records and URL for cold/current/history navigation, an unmapped need, mobile Back and nested source-detail focus return. Check real observations remain distinct from absent results; illustrative wording belongs to the example, not every observation. Confirm no interaction invents facts or borrows another need's evidence.

## Layout, evidence and limits

At the declared desktop and 390 CSS-pixel widths, light/dark and normal/reduced motion, compare the selected Program Design, related documents and calls against matching frozen before screenshots and computed metrics. Inspect the content surface, typography, action bounds, local scrollers, drawer, Comments and toolbar. Use real hit tests and appropriate input for focus/Escape/return; preserve existing Trace/card defaults. A clipped control, inaccessible content or wrong surface fails; natural wrapping with readable content passes. Inspect actual image pixels: a grey image or an absent screenshot is an unknown capture, not a visual pass or a product defect.

The focused wrapper only covers what its current permanent cases actually assert. Separately account for real CLI invalid-input/no-write cases, nonfixture full-source comparison, first-author evidence, the future protected release and the actual published standalone consumer. Reuse a real harness observation when it proves the same outcome on matching dependencies; name any missing assertion, sensitivity check, native interaction or artifact identity as a gap. Do not edit product/tests to make this recipe green. Physical iPhone/Safari and historical truth are outside the evidence from desktop Chromium. Report each supplementary outcome only when its own target-bound evidence is read back; a focused wrapper run does not make unobserved cases pass.

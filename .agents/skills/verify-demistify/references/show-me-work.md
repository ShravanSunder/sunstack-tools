## O1: read the complete composition

The fixed sanitized input must include four sections; primary and routine stories; both decision columns; headline and all three labelled rows; each supported showpiece, plus absent optional forms; More; a record with stable entry IDs and a zero-entry record; an explicitly carried-closed story; ordinary page-note and nested attachment disclosures; and an authored Map whose Needs-you branch links the For-you section. Capture expected content and membership from the authored input **before** rendering, independently of generated metadata.

1. Read each supplied story's headline, labelled rows, optional rich content and state. Open More, the record and individual entries through the reader controls; the full supplied body, inline markup, links and attachments survive, once per ID. Another reference to an entry links to it; it does not duplicate its body. Compare source input and rendered/readback text, IDs, order, grouping and states against the fixed manifest, including absent controls.
2. Run or inspect the matching product-owned checker cases for the complete valid composition and each named malformed cardinality, identity, target, group or total case in O1. Record nonzero fixture counts, actual diagnoses, results and exit codes. Checker success proves its checks, not visible content or factual history.

A silently dropped field, flattened rich content, duplicated ID, fabricated entry or unexpectedly opened record fails. A different allowed wrapper or natural line wrap passes. Sanitized content does not establish private-record preservation.

## O2: native folds and derived counts

On the complete fixture, record expected membership from the authored input: story root, direct More, record list and each direct entry, plus the section's smaller fold. Exclude Map branches, ordinary notes and nested attachment disclosures. Inspect the initial `open` state, manually open one entry, then perform section expand, page collapse, manual story open, page expand, section collapse and the other section's control. After **each** action record every member's actual native `open`, the controls' visible glyph and accessible action, and each excluded disclosure's state. With Map closed and its tree restored, also record each Map branch's `aria-expanded` and `data-collapsed` after every action; bulk controls must not change them.

Compare each section's primary/routine split and its Map total with the independent membership, including empty and routine-only cases and a live addition/removal. The input mutation is a component-integration setup, not an ordinary reader action. A cached action, parent-only expansion, skipped entry, changed unrelated note/Map branch or stale count fails; a semantically equivalent permitted layout passes.

## O3: Map, Comments and destinations

1. Drive Map with real pointer and keyboard. At desktop and narrow width switch Map→Comments using the reachable Comments control, then Comments→Map using the **same live Map trigger** in the standard narrow sheet header. Observe one active sidebar, connected trigger/tree object identity, branch state and actual focus. Close/Escape and resize across 899/900 while each presentation is open; check the original button returns to its reader row, and standard Comments/inspection keeps its modal narrow behavior. Map itself is non-modal, below the actual toolbar, with no backdrop or focus trap; toolbar/Pages remain usable. A separate bottom workspace remains independent.
2. Before each tree destination, close its story and any containing smaller fold while keeping unrelated entries closed. Activate each destination, including one inside smaller; the correct target and ancestors open and the narrow Map closes **before** scrolling it into view. Repeat the current fragment, load cold, and use native back/forward. Compare actual URL/history and visible destination, not URL alone.
3. Cover hash, same-page relative and absolute, other-page and external links, encoded/malformed/missing targets, modified clicks and `target`/`download` behavior as R6 specifies. For rapid competing local destinations, the second target wins; no substitute story is selected. Retain the actual action sequence and visible/focus/state result.

At desktop and narrow widths, run normal motion and real browser-emulated reduced motion. Read the actual Map and Comments panel animation/transition names and durations: normally they use the shared family; under reduced motion the transition is removed or instant. Screenshots alone do not establish motion. For authored malformed or missing targets, check the existing authoring-checker diagnostics in O1. For a missing or malformed fragment activated or loaded at runtime, require the document preserved and no substitute story, with no new runtime diagnostic expected. Set an absolute same-document link from the actual fixture URL as labelled input, then activate it natively.

A modal that hides the live trigger, a cloned replacement, stale close/scroll, wrong-target fallback or synthetic behind-modal click cannot establish this journey. A nonlocal or modified activation that preserves normal browser behavior is an allowed outcome.

## O5: layout and unchanged readers

Use 1280, 420 and 390 CSS-pixel widths, both affected themes and reduced motion. Compare the full reader's story hierarchy, section category bands, quiet surfaces, wrap, one local table surface, original controls, sticky headings and reserved comment controls with the adopted design and the appropriate supplied appearance references. Record actual page and local scroll widths, target/control bounds and screenshots. Use normal UI scroll to reach both ends of any deliberate local rich-view scroller; `documentElement.scrollWidth` alone cannot rule out hidden clipping.

Use native pointer dragging to select text across story body rows and separately in summary text; read the actual selection and confirm the relevant fold state is unchanged. Use keyboard Tab to each fold toggle, Map trigger and story summary; inspect its visible focus and accessible name. A Selection setter or scripted focus alone is not proof.

Hit-test real theme, search, walkthrough, Comments and Map controls with Map absent/present and with a bottom workspace open. Exercise changed interactions at desktop and narrow in each affected theme; preserve unrelated notes, attachments, Trace/card defaults and controls. Compare the same unchanged `#spacing-trace`, `#composition-step > summary` and `#trace-owner` fixture states to the frozen R10 before-state supplied by the commissioner, including 1280/390 × light/dark and relevant typography, colours and geometry. Baseline evidence is not candidate proof; check identity and applicability before reuse. Different permitted line wrapping passes; covered text, inaccessible controls, lost content or changed existing reader defaults fail.

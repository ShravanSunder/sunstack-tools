# Demistify takeover — owner decisions and baseline evidence

Date: 2026-10-14. Branch: `claude/serene-pascal-llse28`, fast-forwarded from `feat/demistify-html-islands` at `a31c1da`. Toolchain: Node 26.12.0 (repo `engines` ≥26 unchanged), pnpm 12.11.2. This file records owner decisions from the takeover discussion with Shravan and the evidence that shaped them. It is the exchange point for other agents working on this branch; add a dated section rather than editing earlier ones.

## Goal (owner, confirmed)

Agents make new explainers cheaply and correctly. The pages load fast as plain web HTML with light and dark themes. Acceptance test: **a small model (Haiku-class subagent), given only the authoring guide and a fact brief, produces a complex explainer people can consume easily** (see D7, D8). Token efficiency of authoring and of the guide itself both count.

## Directives for every iteration (owner)

Judge each Haiku round and each library change against all five:

1. Token efficient for the authoring agent.
2. Easy for a model to use.
3. Compatible with web standards and with what models already understand about HTML.
4. Easy for humans to understand visually: what is going on is apparent from the page.
5. Designed for progressive disclosure of details.

## Decisions (owner, confirmed)

| ID  | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Delivery: an explainer is a small HTML file that loads one shared, cacheable library (folder or CDN URL) by default. An optional bundle step produces a single offline file.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| D2  | Look: keep the current typefaces and the Phosphor regular icon style. Ship only the font weights and icon weight the theme actually uses. Fonts must not block first paint.                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| D3  | Lean details (weights, subsets, loading strategy) are the implementer's call, provided the visible look is preserved.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| D4  | Less choice, more system: no giant lists for agents to pick from. Agents name a meaning; the library chooses icon, color and treatment. The authoring guide must not enumerate a large catalogue (e.g. 1,530 icons).                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| D5  | Icons: Phosphor regular only, subset to a small semantic set (risk, decision, added, removed, step, file, …) that the library maps from meanings. Constraint without pedantry.                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| D6  | Arrows: no crossings, guaranteed by layout. A flow container places connected islands in rows/columns and routes connectors through the gaps (A→C goes around B). Free-form whiteboard arrows stay simple; the library flags an arrow that crosses a box. No general routing engine.                                                                                                                                                                                                                                                                                                                                                                     |
| D7  | Haiku test input: Haiku receives the authoring guide plus a fixed fact brief (the script: content and story). Briefs are complex explainers: the captured planning corpus (3 perspectives, 25 nodes, 24 relationships) plus two more briefs of similar scale. Haiku owns presentation, not research.                                                                                                                                                                                                                                                                                                                                                     |
| D8  | Haiku pass bar is human consumption, not just rendering: a person can scan it easily (clear order and hierarchy, legible diagrams, nothing clipped or crammed, depth held behind inspection rather than walls of text). Judged from screenshots against a short checklist; owner gives the final look. Also required: no console errors, no hand-written CSS, no guessed attributes, visible non-crossing arrows, theme toggle.                                                                                                                                                                                                                          |
| D9  | Vocabulary follows the recurring patterns in [The unreasonable effectiveness of HTML](https://claude.dev/blog/using-claude-code-the-unreasonable-effectiveness-of-html/), where agents hand-write each page; Demistify makes the same pages cheap. Add: annotated code and diffs (margin notes by severity blocking/nit/nice, steps linked to source lines); options with tradeoffs (cards labeled by tradeoff, a recommended pick; TL;DR, gotchas and open questions as callout meanings); simple themed charts from a small inline table (lazy module). Excluded: copy-back export buttons and throwaway interactive editors (sliders, drag-and-drop). |
| D10 | The authoring guide is written in skill format (SKILL.md frontmatter plus a short body) so it can be paired with a skill later.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| D11 | Composition is the island idea: islands compose in any order and any 2D arrangement (grid, flex, absolute) anywhere, not only top-down. The library extracts as much repeated work as it can (surfaces, colours, icons, rendering, inspection, arrows) while keeping pages understandable and plain-HTML compatible. Authored layout CSS (grid/flex/absolute) is legitimate; authored styling (colours, borders, fonts) is not needed and the D8 check targets that, not layout.                                                                                                                                                                         |
| D12 | Pages must not default to a top-down stack: layouts that use the space on desktop and adapt on phones (width-aware grids, spans, sticky side columns, swipe rows, tabs-as-columns, stat tiles beside charts).                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| D13 | Guided routes: authors define one or more named paths through the same islands (presentation-style previous/next with narration); different routes serve different audiences over the same content.                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| D14 | Whiteboard direction: one set of islands, several ways to view it — a map (2D board with pan/zoom and regions), reading flow, and routes as camera paths across the map. Driving use cases: a map of all domain data in one collection that is easy to go through, and a deep dive into one component whose detail islands appear on drill-down.                                                                                                                                                                                                                                                                                                         |
| D15 | Every Haiku test run starts as a fresh agent with no conversation context: only the guide, one brief and an output path.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| D16 | Goals (owner): a library of native UI components (containers, text, layouts, charts, interactive elements); model-generated composition; a shared design system (consistent spacing, typography, borders, interaction patterns); routing and narration for understandability.                                                                                                                                                                                                                                                                                                                                                                            |
| D17 | Minimise git churn: an explainer is one small HTML file loading the library; library improvements reach existing pages without editing them. The authored vocabulary is a backward-compatible contract. Later: compiled builds on Cloudflare with semver; pages pin a major version and receive non-breaking updates.                                                                                                                                                                                                                                                                                                                                    |
| D18 | "Different ways to show the same content" = views and routes over the same hand-written islands (not a data collection rendered many ways).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| D19 | Canvas/whiteboard = the author's own layout (grid, flex or absolute positions) with the library's camera, routes and arrows on top; auto layout remains the default.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| D20 | Depth: one level per page; a component deep dive is its own linked page (composable), reached from its region, with breadcrumbs back. Tours can cross pages as one continuous tour, declared on the overview page in route syntax; position travels in the link; no server and no heavy library. Presentation = spotlight in place.                                                                                                                                                                                                                                                                                                                      |
| D21 | Interactive elements = hover and reveal, navigate and inspect, reveal controls (layer toggles, before/after), step-through diagrams. Not tuning sliders.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| D22 | The drawer (sidebar inspector) is a docked, non-modal, resizable panel that takes space; the main page stays scrollable beside it. The modal remains the large centred view.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| D23 | Add standard components: multi-file code diffs, images (single, gallery, before/after, generated pictures), checklists/task lists, trees.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| D24 | Hosting: the library is served from the web (Cloudflare, semver later) and explainers may be local files. The runtime stays an ES module; the host must send `Access-Control-Allow-Origin: *` on the runtime, chunks and fonts, since a `file://` page has origin `null` and Chrome CORS-checks module scripts and fonts. Explainer-to-explainer links and images use relative paths (same folder, subfolders, `../`) and work both locally and over the network. Local testing uses a server with that header or the offline bundle.                                                                                                                    |
| D25 | Hierarchy of affordances: containers (tabs, grids, flows, boards, regions, author divs) never get inspection controls; they arrange. Islands get one only where it adds something: visuals worth enlarging (diagrams, charts, code, file trees, overflowing content) get sidebar/expand buttons; hidden depth (`slot="details"`) gets a quiet "More ›" link; inline `<details>` are their own affordance; prose, plain cards, callouts and stats get nothing. Routes and diagram links can still open any island in the drawer.                                                                                                                          |
| D26 | Schema-led design: style is constrained by the vocabulary (meaning attributes only, no colours or fonts), while HTML keeps full layout freedom. One vocabulary table is the source for the agent checker (`demistify check`, with `--fix`, `--render` and a Claude Code hook), the element manifest and editor data. Zod Mini is reserved for structured payloads (e.g. chart data); flat string attributes use the plain table.                                                                                                                                                                                                                         |
| D27 | Every card and region carries a tone (its icon and colour); the checker warns when one is missing, and the guide teaches status → tone, timing/location/tradeoff → tag. A curated subject-icon set (`icon`) follows with the components work.                                                                                                                                                                                                                                                                                                                                                                                                            |
| D28 | The authoring guide is progressive: a core `SKILL.md` (about 1.2k tokens: shell, Markdown first, islands, tones and icons, grid and tabs, routes, check) plus small `references/*.md` files (maps and layers, code, trees, pictures, tours) read only when a page needs them. Adopted on round 6 evidence: fewer guide tokens read, equal or better pages, and agents found the right references.                                                                                                                                                                                                                                                        |

## Baseline evidence (observed this session)

Cold load over local HTTP in Chromium, simulated 10 Mbps / 40 ms:

| Page                                  | Transferred | Main costs                                                                                                           |
| ------------------------------------- | ----------- | -------------------------------------------------------------------------------------------------------------------- |
| `html-islands-live.html` (no diagram) | ~443 KiB    | `theme.css` 168 KiB gzip, of which ~200 KB raw is 8 base64 woff2 fonts (render-blocking); full Phosphor font 144 KiB |
| `html-islands-composition-live.html`  | ~949 KiB    | plus the lazy Mermaid chunk, 500 KiB gzip / 2.2 MB raw (beautiful-mermaid + elkjs)                                   |

Authoring: the existing report counts `planning.html` at 4,909 o200k tokens (Markdown-directive prototype: 2,391). Much of it is wrapper markup and formatter indentation inside script blocks.

Haiku baseline: given only `packages/demistify/README.md`, Haiku wrote a 4.6 KB merge-vs-rebase explainer. It rendered with no console errors, both Mermaid diagrams drew, and the Markdown dedented correctly. Failures that a reader would see:

- It hand-wrote ~25 lines of layout CSS because `ex-compare` has no documented child contract. Its borders ignore the theme.
- An `ex-arrow` between two `ex-zoom` boxes is present in the DOM but invisible: the boxes stretch, leaving a ~32 px gap.
- `ex-zoom` has no visible surface or inspect control in that layout, and `ex-decision` ignored the guessed `label`.
- No theme toggle, because the README does not show it.
- It guessed attribute names for `ex-arrow`, `ex-decision`, `ex-callout`, `ex-tabs` labels, and the timeline, layer and file-tree elements.

Reading: the runtime mostly works; the gaps are an undocumented or unforgiving vocabulary and silent failure modes.

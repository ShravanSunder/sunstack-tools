Write TypeScript. Call the Rust engine.

@sunstack/sdk lets a developer or model author the whole configuration as normal typed values, call check or run, and consume concrete typed results. Existing CLI configs still work: load them, make a typed copy, and run the copy.

Current evidence: the packed Mac arm64 SDK compiles and runs outside the repository, including full inline authoring and typed results. This SDK is not published yet. The real provider and all six platform installs have been exercised. Final source checks and independent delivery review remain open.

What types do, and what Rust does

The TS compiler catches keys, variants and result access. Rust still decides nonzero/range limits, globs, marker bindings, references, language and pattern validity. The SDK does not embed a TypeScript compiler in Rust or duplicate those decisions in TS. Run a separate typecheck before executing the TS program.

Can the whole config live in TypeScript?

Yes. The package example below contains the Markdown standard, rule entry, matcher, evidence field, filter, questions, decision graph, model selection and limit. It imports only the SDK. No JSON/YAML definition project or copied fixture hides behind the example.

Complete package example: every definition authored in TS

Functions, imports, loops and composition stay in the caller’s TS program. Pass the resulting data to Rust. The existing engine owns evidence evaluation and decisions; this package adds no AST traversal or codemod rewriting API.

What happens when I load and change a config?

load returns frozen captured values and their origins. Copy the value, change it, and pass that copy to run. Definitions already captured do not get reread from disk.

base_directory resolves definition files. root is the explicit checked directory and can be elsewhere. Result sources distinguish unchanged files, authored inline values and edited values; content and digests describe what actually ran.

What comes back?

A closed outcome union. completed means the call completed; its tagged report status still distinguishes findings, clean, uncertainty and nothing selected. Invalid input, unavailable definitions, partial execution, cancellation and detectable adapter failure stay distinct.

Cancellation uses one AbortSignal per call. It must not cancel a sibling call. An already-aborted signal starts no work. After-dispatch adapter failures say effects are unknown; the SDK does not replay the whole run.

Why isn’t Zod required?

The generated types give compile-time authoring constraints, and Rust performs runtime validation at the engine boundary. Zod would be an optional additional validator. The base package neither imports nor requires it; no Zod exporter is shipped.

Sunstack-owned declarations come from Rust derives. Upstream ast-grep structures use the pinned Rust schema with an upstream-backed typed wrapper. Matcher language names are concrete, but grammar-specific kind strings are only statically constrained where compatible grammar maps actually exist. Rust always compiles the matcher.

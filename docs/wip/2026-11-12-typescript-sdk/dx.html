Write TypeScript. Call the Rust engine.

@sunstack/sdk lets a developer or model author the whole configuration as normal typed values, call check or run, and consume concrete typed results. Existing CLI configs still work: load them, make a typed copy, and run the copy.

The current integration targets SDK 0.15.0, contract revision 7. The examples describe that typed API; current installed-package proof is tracked separately in PR 159. The historical proof snapshots below keep their own versions and do not establish this candidate. The SDK is not published yet.

What types do, and what Rust does

The TS compiler catches keys, variants and result access. Rust still decides nonzero/range limits, globs, marker bindings, references, language and pattern validity. The SDK does not embed a TypeScript compiler in Rust or duplicate those decisions in TS. Run a separate typecheck before executing the TS program.

Can the whole config live in TypeScript?

Yes. The package example below contains the Markdown standard, rule entry, matcher, evidence field, filter, questions, decision graph, model selection and limit. It imports only the SDK. No JSON/YAML definition project or copied fixture hides behind the example.

Complete package example: every definition authored in TS

Functions, imports, loops and composition stay in the caller’s TS program. Pass the resulting data to Rust. The existing engine owns evidence evaluation and decisions; this package adds no AST traversal or codemod rewriting API.

Can I define HTML sections as typed values?

Yes. Native section kinds use the same Rust compiler. A section starts at an h1–h6 heading; full includes its children, own excludes child sections, and enclosing own selects the direct parent’s own text. A top-level section has no enclosing section, so that field is absent. Mechanical fields retain the original markup; asking views use projected visible text.

Markdown units use the same typed boundary

Use markdown_units with unit mode and section, paragraph or list_item. Section fields require exactly the section unit. Markdown follows its parser ranges; the full config, filters and decision graph still live in ordinary TypeScript.

Document conventions are typed configuration values too. Put this evidence value into a complete Configuration; the same fields work on project and captured evidence. Leave them out for standard defaults. GitHub heading anchors and custom HTML conventions are explicit choices.

The compiler catches misspelled keys and unknown schemes. Rust rejects blank tag or attribute names. Without a heading scheme, inferred Markdown fragments return heading_scheme_not_configured; explicit HTML id/name anchors still work. Other unsupported document formats return unsupported_document. skip_tags changes which headings form sections; raw source remains available.

What happens when I load and change a config?

load returns frozen captured values and their origins. Copy the value, change it, and pass that copy to run. Definitions already captured do not get reread from disk.

base_directory resolves definition files. root is the explicit checked directory and can be elsewhere. The captured evidence also contains its document settings: editing only a tag, attribute mapping or heading scheme changes the configuration and its root provenance. A later disk edit changes nothing until reload. Result sources distinguish unchanged files, authored inline values and edited values; content and digests describe what actually ran.

What comes back?

A closed outcome union. completed means the call completed; its tagged report status still distinguishes findings, clean, uncertainty and nothing selected. Invalid input, unavailable definitions, partial execution, cancellation and detectable adapter failure stay distinct.

Cancellation uses one AbortSignal per call. It must not cancel a sibling call. An already-aborted signal starts no work. After-dispatch adapter failures say effects are unknown; the SDK does not replay the whole run.

Why isn’t Zod required?

The generated types give compile-time authoring constraints, and Rust performs runtime validation at the engine boundary. Zod would be an optional additional validator. The base package neither imports nor requires it; no Zod exporter is shipped.

Sunstack-owned declarations come from Rust derives. Upstream ast-grep structures use the pinned Rust schema with an upstream-backed typed wrapper. Matcher language names and rule keys are concrete types. AST kind names and pattern strings remain strings in this SDK: it does not export grammar-specific kind maps. Rust compiles the matcher and rejects unsupported values.

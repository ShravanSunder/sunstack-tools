A partial run keeps findings and gaps together

Missing model credentials must stop only the work that actually needs model capability. Independent checks still finish; known affected pieces receive explicit unavailable results; unresolved selection remains a dependency gap rather than fabricated evidence.

The Requirements own the authorized needs. This page owns the observable rules. Exact enum placement, serialized variant shapes and execution owners belong in Program Design. Verification Design chooses the deciding observations.

The same run facts reach every caller

The CLI agent, typed SDK consumer and saved-report reader see different presentations of the same execution. A missing credential is an execution-availability condition; malformed global definitions remain an admission refusal. An agent's manual review may resolve its own task, but cannot retroactively turn an unrun engine judgment into a pass.

These are consumer relationships, not internal components. The provider receives nothing for locally unavailable work. Existing requests that really reached a provider retain their observed failure evidence.

Keep an unavailable judgment attached to its real subject

A run may know the source piece that needs a judgment while being unable to perform it. It may instead need a selection answer before the final piece exists. Those are different facts: the first can have a per-piece unavailable result; the second has a prerequisite gap, without an invented final piece.

The diagram shows cardinality within one run. Subject identity includes its authored definition and original source witness; repeating the run creates a new assessment, not a different source identity. A dependency on an undecided selector does not establish a final child subject.

Continue only work whose prerequisites are satisfied

Mechanical evaluation can finish before reaching an authored question. Conversely, a mechanical rule behind a judged filter still needs that filter's answer. Missing credentials must be classified at the actually needed capability, rather than by whether questions happen to be present in a definition.

Partial status must not hide useful findings

A partial run says both what completed and what remains unavailable. The consumer can require complete coverage using its exit/status while still inspecting real findings. It must not mistake a provider-free partial run for keyless preparation.

Each obligation has a deciding counterexample

The problem P1 is whole-run credential refusal losing independent results; outcome O1 is a useful, truthful partial run. P2 is conflating unavailability, negative judgment and actual provider failure; O2 keeps their evidence distinct. P3 is losing those distinctions across CLI, typed code and saved reports; O3 preserves them across the consumer boundary.

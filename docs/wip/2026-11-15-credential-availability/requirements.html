Useful checks without a model credential

An agent running a mixed rulebook should still receive its independent mechanical findings when the model credential is unavailable. Work that needs a judgment must remain visibly unavailable, so useful partial output cannot be mistaken for a complete check.

This is one concern: make an ordinary lint run useful and truthful under missing execution capability. The observable contract defines what callers can rely on; the planned proof view shows how each need will be checked.

Keep the useful part of an ordinary run

An agent follows a skill's normal lint command, reads its findings and gaps, and decides what to repair. The reported PR227 failure interrupts that job: adding two judged nudges beside three mechanical ones makes a missing credential refuse all five. The source confirms whole-run refusal; the PR227 live failure is reported evidence rather than an independently reproduced run.

The desired change removes the need to discover a second execution mode. It does not make an agent's own judgment a substitute for a model check that did not run. The needs below share required priority, assigned by the Rules Lead's commission and accepted direction; none is an optional enhancement.

Read partial results without writing another runner

A TypeScript consumer already authors a configuration, calls the Rust-backed SDK and handles a closed result union. The missing capability is truthful partial evaluation in that existing path. A future SDK consumer must receive the same mechanical findings and unavailable work as the CLI, including when reading a saved report later.

This journey serves U2, U3 and U4. The CLI failure has source and reported-runtime evidence. Equivalent SDK pain has not been measured with new agents; the SDK requirement comes from the explicit shared-contract direction, rather than an invented usability score.

Default partial execution is the authorized direction

The Rules Lead's accepted direction selects default partial execution, with no opt-in mode: independent work continues; unavailable judgments never pass; dependent work stays blocked; no pieces, attempts or receipts are fabricated; partial exit is 3; Rust owns the typed reason; the SDK contract revision advances.

The original gap10 commission, titled “a missing model credential refuses the whole lint run”, supplies the need and generic engine boundary. The accepted direction is commissioner authority, not a verbatim owner quotation. The owner's instructions separately require strict Rust/TypeScript contracts, discriminated unions and no TypeScript enums.

Change execution availability, preserve admission

Extend the existing generic engine and SDK. No rule-specific workaround, skill rewrite, second runner, opt-in strict/partial policy, dummy key or paid inference is part of this work. Static admission remains a separate operation. Configuration errors do not become executable partial inputs merely because credentials are unavailable.

Preserve the SDK static check's existing no-credential, no-provider and no-checked-input guarantee. The ordinary-run change does not preserve the old refusal before logical checked-input acquisition. That old order was not a promise of zero physical source reads: change capture and historical case snapshots can read earlier.

Success means real local findings survive, every unavailable obligation is accounted for, and the CLI, SDK, saved reports and PR227 caller expose those facts consistently. Source inspection alone does not establish that final integration. Hosted model quality, credential setup and SDK npm bootstrap are outside this design's outcome.

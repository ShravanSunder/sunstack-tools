## Proof plan

Authoring basis: user-directed intent, no failing baseline.
Reference-skill posture: drafted from approved intent until the named fresh composition is observed.
Before guide writing/use, preserve the independently fixed case/checks outside the product/guide writer's working directory.
Give a fresh Luna only a realistic author task, its supplied facts, candidate matching API guide/binding and its own output home, with no evaluation framing, expected checks, lab answer or implementation.
Retain the first submitted source before external feedback, prepare/check a separate copy if needed, compare every supplied meaning/form/state/link and render through actual public assets.
At most one separately retained guided correction may follow the first scored submission; it never replaces the first result.
Use supported host observation to establish the guide copy/actions where available; a continuation gap or unobserved load remains named and limits the claim.
No prior-guide control exists, so no improvement claim. One named output cannot establish general author reliability or total usage/cost.
Static/package checks establish structure and implemented API only; independent review supplies no missing runtime or author proof.

# What the guide must teach

The following obligations implement the success definition without extending the component contract.

- G1: The main guide routes page-level `ex-map`, `ex-story` and `ex-section` compositions to `references/stories.md` and keeps Trace's ordered-evidence route distinct.
- G2: The reference teaches exactly one direct native `details[id]` root per `ex-story`, with one summary and the required headline, happened, for-you, next and record children, plus at most one showpiece and More; its author-written record summary names the actual supplied entry count.
- G3: The reference shows supported rich HTML inside those children, complete native record entries with stable IDs, and ordinary links for repeated references instead of duplicated bodies.
- G4: The reference states story-specific new-composition defaults (stories open; depth/entries/routine folds closed) and loads the existing content.md carried-form/state rule for supplied or requested states instead of creating a competing exception policy.
- G5: The reference teaches section metadata, derived primary/routine counts, the single native smaller fold at the section's end with an author-written summary count matching its actual members, and page/section bulk membership/exclusions; non-story content such as two decision columns uses ordinary HTML/ex-grid outside those counts.
- G6: The reference teaches one Map per page with exactly one Tree, its scope binding, one top-level linked section branch per section using fragment-only `#id` hrefs and no authored total, and the Needs-you/For-you relationship as an example; its example uses `folded:` while trees.md remains the sole grammar owner.
- G7: The reference describes the actual shared non-modal Map, Comments replacement and original trigger behavior, narrow toolbar clearance, native destination reveal/repeat, M with the same C protected-input policy, and the limits of checker-only URL resolution; an unresolved section-branch warning means the author must fix that branch rather than treat generic warning advice as proof of coverage.
- G8: One complete four-section example with separately written public-safe stories, entry bodies, IDs, titles, state pattern and Map labels distinct from the O7 request, with primary/routine stories, rich showpiece, More, records, stable links and Map, is available from the reference without reading runtime source or private files.
- G9: The change preserves existing binding/trust and single-static-lint workflow; component regression proof stays in this repository's development process.

## Rules and transfer

These are rules scoped to Demistify, the product this guide documents; they are not new generic workflow policy.

| Rule | Different valid case | Bad case not named by the rule | Verdict |
| --- | --- | --- | --- |
| Retain supplied meaning, identity, grouping and state; infer no status/tone/classification or prose claim from importance, and compute an author-written cardinality only from the supplied members when its label is not already supplied. | An incident-review story retains a rich command transcript and a deliberately open record. | An account receives an invented success tone or routine classification, or an inconsistent claimed count without flagging the source conflict. | Pass: allows the first, rejects the second. |
| Use Story for an account and its record; use Trace when the explanation's ordered steps are its meaning. | A compiler-change account has rows and supporting entries, while a debugging procedure remains ordered. | An unordered audit finding list is forced into numbered evidence steps. | Pass: the reader's relationship chooses the view. |
| Derive only the header primary/routine split, Map section totals and bulk membership from native structure; author the record-entry and smaller-fold summary counts to match their supplied members. | A release note section has routine items and an empty section. | A performance report types a stale total into its Map label. | Pass: stable structural rule across subjects. |
| Reuse the shared Map/sidebar/control interaction instead of adding document-specific presentation code. | A library maintenance account and a migration account both use one Map and Comments owner. | An author builds an independent overlay with cloned IDs. | Pass: the same product boundary applies. |

The reference teaches the concrete markup for these rules beside positive examples. Historical implementation/debugging details stay in task evidence, not in shipped guidance.

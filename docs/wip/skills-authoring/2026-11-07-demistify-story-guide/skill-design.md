## Reference contract

Callers, with the main chooser predicate as the one selection definition:

- Main chooser: IF the page needs a page-level `ex-map` reader panel, an `ex-story` account with labelled rows/supporting record, or `ex-section` story scopes, load `references/stories.md` and return the supported composition, authored fields/states and stable destinations.
- `navigation.md`: IF a page needs the reader Map panel, load `stories.md` and return its scope binding and linked section/story destinations.
- `inspection.md`: IF the intended panel is page Map navigation, load `stories.md` and return the shared Map/Comments arrangement rather than a content inspector or bottom workspace.
- `maps.md`: IF “map” means the page reader navigation panel rather than spatial Board regions, load `stories.md` and return `ex-map` composition and scope targets.
- `trees.md`: IF a Tree is the page reader Map rather than a `layout="map"` drawing, load `stories.md` and return its `ex-map` container, top-level section branches and scope binding.
- `traces.md` and `cards-and-callouts.md`: IF the supplied unit is an account with labelled rows and supporting record rather than an ordered step or named card, load `stories.md` and return the native story/section/Map composition.

Input: supplied account prose, groups, rich bodies, IDs/links and initial states. Requested work: compose those meanings with the supported native elements, rather than infer them from statuses. Return: complete HTML using the supported element/slot cardinality, section placement and Map destinations, with no private style/interaction code. Completion: every supplied field occurs once, linked IDs resolve, state follows the existing carried-state rule, record/smaller summary counts match their members and supplied count conflicts are named rather than silently corrected, and the main guide's one lint pass accepts it. A static pass is not claimed to prove readability or factual history.

Local reference links point only to the existing `content.md`, `layouts.md`, `trees.md`, `navigation.md`, `traces.md` and `inspection.md` owners for their distinct detail; they do not introduce new cross-plugin calls. Binding/trust comes from the unchanged main path before any view selection. The new complete example inside the teaching reference has its own facts/IDs from a different subject and differs from the O7 request. The original app fixture stays a regression consumer outside the author's inputs, never copied into the guide. stories.md separates page Map navigation, Board mode="map" and Tree layout="map" in its opening.

The reference's exact markup is the accepted Program Design's `ex-document`, `ex-section`, `ex-story` with native `details/summary` and named slots, `ex-fold-toggle[for]`, and `ex-map[for] > ex-tree`. No schema/JSON story API is introduced. Supported subject/time/icon/tone/series attributes come from actual vocabulary. The reference explicitly shows new-story `open` and closed depth, and uses a conditional load of content.md for carried/requested state under its existing exception rule. Section totals are never typed into labels; the Map reads the same member set. More and record entries use native `open`, not a new auto-expand option. The record and smaller summary count text is author-written from supplied membership; it is not renderer-derived or checker-certified. M toggles the same Map as its button under the reviewed U3/R5 addition.

# Verify the pointer and the composition

Authoring basis is user-directed intent. Current posture: drafted from approved intent, not yet guide-evaluated. This is a product reference skill, so proof asks whether its pointer reaches the right detail and a fresh reader applies it. No failing baseline is manufactured and no improvement claim is planned without a fresh old-guide control.

## Routes decided before the author runs

| Obligation / standard | Route and reason |
| --- | --- |
| G1 conditional pointer and no trigger change | Review checks the actual chooser row and unchanged frontmatter; no two-prompt trigger trial, because the description is not written/altered. |
| G2 exact cardinality/slots | Deterministic product checker accepts the complete example and rejects named malformed cases; review compares guidance to actual shared vocabulary/runtime guards. |
| G3 rich content/identity/links | Existing fixed-input source/readback plus first-author artifact comparison; structure alone cannot settle retained meaning. |
| G4 defaults and carried state | Fresh composition and initial native-state readback, with closed carried-story and absent-option controls; this is an agent-action eval. |
| G5 scopes/counts/exclusions | Native/component integration cases prove library mechanics; fresh author artifact proves the guide arranged supplied groups correctly. |
| G6 Map/marker semantics | Existing tree/Map checker and real parser evidence plus guide artifact; review checks only actual supported syntax is taught. |
| G7 sidebar/navigation description | Review source against accepted product outcomes and the S3 target-bound native/permanent-harness evidence; no new behavior is inferred from guide prose. |
| G8 complete example | Real source checker, matching renderer and first-author rendered interaction; a code fence alone is insufficient. |
| G9 unchanged binding/trust/lint | Scoped diff review and existing package/link checks; no new sensitive surface is allowed. |
| One meaning/home and complete calls | Review-only: the unit of evidence needs main chooser, reference body and consumers together. Existing skill rules may nudge; no new rules entry or marker is introduced. |
| Positive required slots and observable conditions | Review checks each changed sentence against the success gap and deletion test; the fresh artifact observes whether the wording is applied. |
| No task history in shipped guide | Whole changed-reference review; the design/debugging record stays in ignored task evidence. |

No custom judged-rule infrastructure is added for this small product guide change. Run the available skill rules at creation self-check and report actual nudges/uncertain/gaps, not invented passes. A missing rule engine is named separately and does not replace review/evaluation.

The record and smaller summary strings are withheld from the content-only request so the fresh artifact exposes whether the reference teaches their actual cardinalities. A review check also compares those count instructions against runtime ownership; the checker does not validate their numbers.

## First-author artifact

Before dispatch, freeze the matching complete candidate guide/asset binding and the content-only request `tmp/verification/demistify/show-me-s4/author-input.md`; its independent expected source manifest remains outside the author's allowed directories. Before dispatch, inspect every frozen guide file against the request's distinctive story/entry IDs, titles, bodies and Map leaf labels, record any meaningful overlap and reject a matching complete answer; shared API labels, cardinality syntax and the generic section skeleton are allowed. The guide's worked example is a different subject with different facts/IDs/state pattern. Strip source-structure rules (smaller fold placement and omitted Map totals) from the request, leaving supplied classification/grouping/state/destinations only.

The author receives the guide's full packaged reference folder, that request, exact binding and output path only. It receives no prototype, design, implementation, original composed HTML, expected checker results or parent conversation. The request asks for an ordinary page, without revealing the evaluation or check list.

A new Luna session with no authoring history writes its first HTML. Preserve that exact first submitted file before feedback, then run the real checker and compare every supplied field/ID/link/group/state and rich form to the fixed input. Observe its built composition through O1/O3 on matching real assets. If it fails, preserve the failure, repair guide-owned teaching, then use a different fresh author; do not edit the first output into a pass. The supported conclusion is one named first-composition case, not a general benchmark.

Host-visible action records establish which candidate guide copy was loaded. If the host cannot provide that record, the artifact may be inspected but guide-use behavior stays unverified. Do not infer it from the author's reply. Static guidance/markup checks do not count as this behavior result.

Document evidence

Rules that judge Markdown skills, HTML design pages and other linked text documents judge whatever a heading cuts out, and the owner found those chunks wrong. This design set proposes that they judge what a reader reads as one explanation, with the context and links it needs, and that this evidence be proven before rules are tuned on it.

Four choices on the Requirements page:

  • Is the list of parts right?
  • Is the goal boundary right?
  • Can the engine's native outline stand beside ast-grep (U1)?
  • When should backlinks and multi-hop links ship?

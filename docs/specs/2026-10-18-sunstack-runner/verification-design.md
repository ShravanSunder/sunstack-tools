## Shared observations

### S1 lint fixture repositories

Small Git repositories built by a script, each with a `sunstack.lint.json`, rule sets and target files, plus an expected-results file beside each. Together they cover:
- every exit code;
- every severity case;
- invalid configs;
- the default, `--since` and `--all` scopes in a scripted history, including a changed rule and a changed config;
- ignored and context files;
- and all four formats.

They run against the dev build and the release builds, with an unreachable backend endpoint for every fixture that must make no model request. Lifetime: lasting, as `verify-sunstack-rule`'s lint-runner journey. Serves U1, U2, U4, U5, U6.

### S2 clean-container matrix

Each release build runs in fresh `alpine` and `debian:stable-slim` containers pinned by digest, x64 and arm64, read-only and without network. Each run does `--version`, `lint --check` and one fixture lint, and inspects the binary's linkage. The macOS builds run on a fresh GitHub-hosted macOS runner in the private test repository (S4), with the x64 build under Rosetta, and the arm64 build also runs on the local Mac. Lifetime: lasting, rerun every release. Serves U8, U9.

### S3 hosted judgment

One judged rule over a fixture whose correct verdict is known to fail. It runs from the static Linux arm64 build in Alpine with the CA bundle hidden. The key is supplied to that one command from the owner's 1Password item and is never printed. Lifetime: lasting, run when the backend or the build changes. Serves U7.

### S4 release rehearsal

A private test repository holds a copy of `sunstack-tools` with the generated cargo-dist workflow, plus a private test tap. Pushing two test tags, an older and a newer version, runs the real workflow twice. Their release files are downloaded with an authenticated `gh release download`, then served from a local mirror so that the installers, which cannot authenticate, fetch those exact bytes. Installation runs through Homebrew, the shell installer (with the older version requested) and npm, in three places: a clean `node` container, local Linux containers, and fresh GitHub-hosted macOS and Linux runners in the test repository, which download the release with the workflow token and install from a mirror on the runner. Lifetime: lasting, the pre-release check for each version. Serves U2, U8, U10, U11.

## Unverified at delivery

- Installing from the public GitHub, Homebrew tap and npm addresses. These exist only after the first public release, which is not part of this work.
- Intel Mac hardware. The x64 macOS build runs under Rosetta on Apple silicon here.
- Linux distributions other than Alpine and Debian, private CA certificates, and Windows.

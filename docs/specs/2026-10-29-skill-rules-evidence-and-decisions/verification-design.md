# Skill rules on evidence and decisions: verification design

How each requirement in [Requirements](requirements.md) will be shown to hold, against the [Specification](specification.md)'s proof obligations and the [Program Design](program-design.md)'s seams. Nothing here has been observed yet.

The project's verification skill is `.agents/skills/verify-sunstack-rule/`. Its S1 lint-runner journey (`references/lint-runner.md`, `scripts/lint_fixtures.py`) and S3 hosted journey (`references/hosted-decisions.md`, `scripts/hosted_lint.py`) drive `sunstack lint` with today's config shape. This change updates both to the new shape and adds one lasting journey, "rulebook lint", that drives the binary over a fixture repository holding a copy of `verification-design/SKILL.md` and `practices-retrospective/SKILL.md` from sunstack `565d763f`, an evidence project built from the confirmed page's tested layout, and the K001–K003 rule entries.

## Shared observation: "rulebook lint"

One fixture repository, four steps through the binary built from the change: (1) `--evidence` for every kind, compared with expected pieces; (2) a full run against the loopback endpoint scripted per worked example; (3) change-scope runs in a temporary Git copy; (4) the skip and malformed cases. It serves U1, U2, U5, U8, U10 and U12. The hosted variant reuses S3's driver with the real key and runs once per release candidate.

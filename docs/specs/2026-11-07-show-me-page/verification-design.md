# Prove the shared page through its real reader

The decisive result is a page composed from the released library and guide that keeps the approved story hierarchy, native folds and Map behavior. Local source checks and browser tests prepare that result; they cannot replace it. This document plans observations. It reports no product run.

## What will show each need is met

### U1: Read a story and its record

**Proven by:** Open the same story in the approved view and shared composition, read the headline and three rows, then open More and each supporting entry without losing the story or rich attachment.

**Outside this observation:** Historical claims in supplied text are not certified.

### U2: Scan and expand four sections

**Proven by:** Scroll each section under the toolbar, check its primary/routine count against Map, and expand/collapse from both page and section controls after manual changes.

**Outside this observation:** Unrelated custom page layouts are not generalised from this composition.

### U3: Reach stories with Map and Comments

**Proven by:** Switch both ways between Map and Comments, then follow every story link including one already in the URL; each target opens in view while unrelated records stay closed.

**Outside this observation:** Desktop emulation is not physical iPhone/Safari proof.

### U4: Understand links and folded branches

**Proven by:** Read actual rendered in-page/outbound icons and operate marked/unmarked tree branches independently of their links.

**Outside this observation:** Unlisted Markdown syntaxes are not implied supported.

### U5: Author with shared parts

**Proven by:** Compose a complete example from the matching guide, compare its source and rendered content with the fixed supplied set, and check that it needs no private CSS or interaction scripts.

**Outside this observation:** A sanitized public example cannot prove private record fidelity.

### U6: Use it after independent checks

**Proven by:** After independent implementation review and release, Terra reads and operates the released-only private composition against the corrected reference at the required widths.

**Outside this observation:** No merge, source version or HTTP acknowledgement alone is acceptance.

References and semantics come from [Requirements](requirements.md) and [R1–R12 / V1–V12](specification.md#contract-and-proof-obligations). Owners and real observation seams are in the [Program Design trace](program-design.md#how-each-obligation-reaches-proof).

## Shared observations

**O1 — complete controlled composition, lasting journey needed.** A sanitized fixed input contains four sections, primary and routine stories, the two decision columns, all three labelled rows, one example of each supported showpiece form, More, records with stable entry IDs and a zero-entry record. Each optional form has an absent control. At least one story is explicitly carried closed; normal new examples are open. More, record lists, entries and smaller groups start closed. Ordinary page-note details and a nested attachment disclosure are outside bulk membership. The Map has Needs you linked to For-you, authored work-parts, then three other section branches; section totals are un-authored and derived. The real built runtime/theme and font are loaded, not source-module substitutes.

The input manifest is fixed before observation from authored HTML and reviewed expected content, not read back from renderer-generated metadata. Read source and rendered text, inline markup, links, order, IDs, supplied state, table cells, actual SVG labels and entry bodies. Every full body appears once. The public checker accepts the complete composition and rejects missing/duplicate required slots, duplicate IDs, unresolved targets, more than one showpiece/Map, misplaced smaller groups, missing section branches and stale authored Map totals. Preserve rendered content and actual diagnoses for malformed inputs. A checker's exit proves its named authoring rules only.

**O2 — native disclosure scope, lasting journey needed.** On O1's page, inspect initial state, manually open one record entry, then use section expand, page collapse, manual story open, page expand, section collapse and the other section's control. Record each listed member's actual `open`, each control's visible glyph and accessible action, and excluded notes/attachment state. With Map closed and its tree restored at its origin, also record every Map branch's `aria-expanded` and `data-collapsed` after each action; bulk controls must leave those states unchanged. Expansion must reach each individual entry, not merely its closed parent; collapse must close every member in scope. Split header and Map total agree with explicit membership, including empty/routine-only cases and a live member addition/removal. Mutating input for the count boundary is a component integration case; native click/keyboard drives the actual controls. Use no mock disclosure state or remembered control boolean.

**O3 — Map and fragment navigation, lasting journey needed.** Drive the real Map trigger with pointer and keyboard. On desktop and narrow layouts switch Map→Comments using Comments, then Comments→Map using the live Map trigger in the standard narrow sheet header. Check that exactly one sidebar is present, the same tree/trigger nodes survive, branch state stays intact, focus is returned to the appropriate connected trigger and the button returns to its row after Close or resize. Resize while each presentation is open across 899/900; exercise Escape and Close. While Map is open the toolbar/Pages controls are usable, the panel begins below its actual lower edge, no backdrop covers it and focus is not trapped. Standard Comments/inspection keeps its established modal narrow behavior; bottom workspaces still coexist independently.

Follow each story destination, including one inside the smaller fold. Before activation, close the story and its containing group while keeping unrelated entries closed. The narrow Map must close before the revealed story is scrolled into view. Repeat the already-current fragment, load it cold, and use native back/forward. Exercise `#id`, same-page relative and absolute forms, another-page fragment, external URL, encoded fragment, malformed and missing targets, modified clicks and `target`/`download`. The intended target and ancestors open; another story is never substituted. A rapid second local destination must win over an earlier pending target resolution. Compare URL/history and actual visible destination, not URL alone.

At desktop and narrow width, run with normal motion and real browser-emulated reduced motion. Read actual Map and Comments panel animation/transition names and durations: the shared family applies normally; reduced motion removes or makes the transition instant. Screenshot appearance alone cannot establish this. Authored malformed or missing link targets are decided by the existing checker diagnostics in O1; runtime activation or cold load of a missing/malformed fragment must preserve the document and substitute no story, with no new runtime diagnostic expected. Absolute same-document links use the actual fixture URL as a labelled input setup, then native activation.

**O4 — tree parsing and shipped icons.** Focused parser/URL classification checks decide plain prefix and URL identity; real tree DOM plus the built packaged font decides its visible controls. Include marked/unmarked nested branches, checklist before marker, tone after marker, link labels, inline-code marker, literal leaf marker, loose paragraphs and Unicode chevrons; a leading `>` still parses as blockquote. All expected label content survives. Fold controls change only their branches; links retain href. Read packaged CSS/font subset membership and actual painted icon glyphs for `arrow-bend-down-right`, `arrow-up-right`, `caret-circle-double-down` and `caret-circle-double-up`; a class name without a glyph is a failure. New marker/default checks join the permanent component browser case, not a one-off automation driver.

**O5 — layout and unchanged readers.** Inspect O1 at 1280 and 420, plus the repository's 390 CSS-pixel width, light/dark and reduced motion. Compare the supplied reference pictures and authored CSS/HTML intent to the new screenshots: compact row hierarchy, quiet neutral section content, existing category header band, wrap, one local table surface, original button colours, sticky headers, reserved comment controls, usable target sizes and complete rich content. Page overflow or hidden clipped content fails; a deliberate rich-view local scroller must reach every endpoint. Exercise the changed interactions at desktop and narrow width in each affected theme. Reuse applicable unchanged real-path assertions; add no duplicate manual journey solely to repeat them. New shared-control placement must be hit-testable with Map absent/present and with a bottom workspace open. Theme/search/walkthrough/Comments controls remain reachable after open/close/resize; existing trace and card defaults retain their prior typography and surfaces.

Before product edits, capture the existing `review-ui/content-spacing.html` fixture's `#spacing-trace`, `#composition-step > summary` and `#trace-owner` against the complete base `26b316c` build, in both themes at desktop/390. Keep screenshots and computed background, font family/size/weight/line-height, spacing and control colours from that frozen baseline; compare the same native fixture/targets on the candidate. A global surface-token or Trace typography change must fail even if the new story looks correct. This is a baseline observation, not a fixture rebuilt from the new renderer's expected styles. Also use native pointer text selection across story body rows and summary text and read the selected text plus unchanged fold state; use keyboard Tab to each fold toggle, Map trigger and story summary, and inspect visible focus and accessible name. Internal Selection setters and scripted `.focus()` alone do not prove these outcomes.

**O7 — independent guide-only composition, temporary journey.** A fresh Luna author receives only the matching local candidate guide (all packaged references), the fixed sanitized story/entry input set and the required output path/binding. It receives no prototype, private reference, design documents, implementation diff or prior conversation. Record the exact allowed inputs and preserve its first submitted composition before any feedback. Judge that first artifact against O1's input and R11: supported syntax, complete grouping/fields/links/states, no private CSS or executable interaction, and a real static check plus rendered interaction. A guide missing a required rule must cause a failing result rather than being repaired privately by an informed author. If it fails, improve the guide and use another fresh first-composition trial; retain the failure. This bounded case establishes that the guide can carry this task, not a general author-capability score.

**O6 — released-only private composition, temporary journey.** After source review, required checks and independent implementation review, prepare the library's normal release artifacts and matching guide through its existing release workflow. Observe the actual hosted runtime, stylesheet, font, lazy chunks and guide from that release. The private page uses only those matching released resources; no local source import, source-worktree asset, private style/script or prototype fallback is permitted. Fix the supplied private story/entry input set from the frozen reference before migration and compare its exact texts, rich forms, IDs, links, group/order and states to the resulting source/readback. A carried field cannot silently disappear because the new interface lacks a slot.

The independent Terra evaluator then compares the page with the corrected reference, operates O2/O3, and reads representative rich content at 1280/420. This is an outcome check, not an assertion that every historical claim is true. The full entry input/readback comparison establishes preservation; sampling alone cannot establish it. The owner receives the usable page only after this result and the library review. Source/code review, local fixture success, release preparation, publication and hosted reader success remain separate evidence classes.

## Evidence already available for reuse

The existing `verify-demistify` skill and its journey source map cover frozen built-library launch, Markdown/source, fragments, tree labels, inspection and Comments. Its current browser harness snapshots real dist assets and consumer output into fresh same-origin frames. `openFixture` waits for upgraded navigation, stylesheet and fonts; individual cases wait for their actual rendered outcome. A listening port or `prepared` attribute alone is not its readiness proof.

The source-read cold-fragment case in `document.browser.test.ts` reaches `#notes--recovery` and `#plan-diagram` through the full built runtime before any click. The sidebar replacement case drives two real inspection controls and checks the retained content, target position and returned focus. Those establish regression expectations for existing paths, not Map coverage. `drawer.browser.test.ts` drives real bottom workspaces, native Escape, phone body containment, and desktop theme/Comments/search hit testing, including restored controls and live walkthrough/diagnostic overlays. These are applicable R10 regressions because the control host changes. Reuse their actual current-target results, rather than carrying historical counts forward.

No existing lasting journey names the new story/section/Map surface. O1/O2/O3/O5 are needed extensions in the project's permanent harness and `verify-demistify` recipe. Product tests remain the implementation's responsibility; the paired Verifier maintains the declared journey/observation recipe. This plan introduces no separate Playwright driver, application test mode or mocked production state. Browser automation already inside the repository harness is distinct from the requested direct Chrome evaluation.

## Reference limits stay explicit

- **G1:** available reference pictures are dark 1400/400, not exact 1280/420/390 or light. Their hierarchy and styling, plus frozen authored layout, are the appearance reference; no exact-pixel comparison at absent sizes is claimed. Candidate views at every required size/theme still must be inspected. Light follows shared theme semantics while retaining the same hierarchy.
- **G2:** the corrected Map header, new jump icon and folded-marker syntax have no old screenshot. Their explicit C5/C7/C8 contracts are the reference, not invented golden pixels.
- **G3:** frozen prototype interaction is source-known; executing its file URL was denied. Do not retry that action through another surface, agent, proxy or copied HTTP target. The candidate's real interactions must satisfy the explicit contract; prototype execution is not required as their oracle.
- **G4:** the reviewer's access to some owner-authority pushes is attributed. The Lead has opened the actual commission/correction messages, and Requirements fixes those authorities. This does not reduce required runtime coverage.

These limits waive no candidate observation. A required observation that cannot run remains incomplete and returns its exact blocker; it does not become a source-only pass. The intended native Chromium/Chrome targets do not claim physical touch hardware or Safari support from CSS-width emulation. No account/backend is needed for the public-safe composition. Release access and actual final Chrome interaction feasibility must be checked before their dependent work is declared ready.

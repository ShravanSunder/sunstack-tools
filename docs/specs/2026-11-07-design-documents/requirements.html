Release the approved document browsers

The owner wants the Requirements and call-stack browsers he designed in the lab to be reusable released components, preserving their information and selected design. Shipping only the drawer shell left that request unfinished. This set governs that remaining delivery.

The chosen view is requirements.html?need=U2&stage=program-design#program-design-U2. Layout and card choices are not reopened. The public elements proposed in Program Design are draft contracts until implementation, review and protected release complete.

Who needs it

The owner reads a need with its rule, structural explanation, checks and call path. Agent authors compose and update that collection without copying app code or maintaining duplicate prose. Workflow skills teach the released interface; reviewers need the same stable identities and inspectable evidence.

Boundary

One concern: publish the already selected document-reading components. Library rendering/styles/schema/preparation/checker/guide may change; illustrative content, archives and the demo remain in the app and consume the public implementation. No framework/backend, Router ingestion, arbitrary graph platform, cross-page HTML transclusion, count-free sections, saved reader preferences or design-skill policy rewrite is included. The peer Lead owns workflow teaching; Root owns this release. Existing shared readers and their defaults remain protected.

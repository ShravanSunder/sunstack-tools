Checks to retain and extend

Existing collection-entry.test.ts and collection-entry.browser.test.ts retain nonfixture identity/default coverage; migrate their imports/fixtures to the public entry. Existing real lab cases in drawer.browser.test.ts and choices-comments.browser.test.ts retain Comments, nested Escape/lifecycle, source card, levels-open and selected surfaces. Add one stable assertion for S2's exact compact rule before changing its hook, a trailing-note sensitivity control, and an internal-fragment/ARIA remapping case. No test mirrors a production helper as oracle.

Fresh author receives only the candidate public guide, supplied independent facts/schema and destination. Score first submitted pages before feedback with real CLI and source-derived expected facts; at most one separately retained guided correction for comparison, no hidden Root polish counted as author success. A single trial demonstrates that case, not general ease. The author sees no approved answer source.

The real R7/C7/V7 browser source/revision case keeps the reviewed root markup and document identity fixed while changing an out-of-root record body and re-preparing; the loaded browser's computed review revision must change. The unchanged prepare/reload control must keep its revision. Run two local Markdown edit → prepare → load rounds; the actual revision must change each time, while authored src remains intact. A remote or missing source fails preparation without changing prior output. Separately load an unprepared page and an invalid/version-mismatched carrier page: the reader diagnoses it, Comments opens and identity resolves, with no unregistered-source error. Testing only the collection hash helper cannot establish this registration/timing contract.

Run existing scoped OXC/format/TypeScript gates, build the complete library and PoC, full relevant Node/browser suite at the final implementation batch, and protected release checks. The independent verifier checks exact target identities before reusing prior evidence. A grey screenshot or wrapperexception establishes neither pagefailure nor a visualpass; diagnose the actual route and preserve raw errors.

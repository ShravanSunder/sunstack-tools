Sunstack TypeScript SDK · Full design

TypeScript becomes another typed consumer of Sunstack’s Rust engine. Existing CLI/config files stay supported. A caller loads an immutable captured configuration or authors complete definitions in TypeScript, then checks or explicitly runs them through the same Rust policy.

These are four separate design documents. They describe the intended complete SDK; the earlier experiment is not the implementation of this design.

The design’s main choices

The selected target uses a native npm adapter over shared Rust entry points; it does not embed a TS runtime or duplicate engine policy. Sunstack-owned contracts are macro-generated. Pinned upstream ast-grep structural declarations use its Rust schema as a documented external-type exception, with no fork or false grammar-map claim. See the alternatives and costs in Program Design.

Loaded snapshots contain the actual definitions used; direct authoring accepts complete values and optional file references. Per-call context replaces ambient CWD dependence for SDK execution. SDK results carry explicit source origins; the existing CLI saved-report format remains unchanged. No SDK report writer or persisted-format migration is introduced.

Review and delivery boundary

These pages define the intended SDK. Authoring checks and design review are not implementation proof or owner approval to publish. Implementation planning follows the reviewed design; the seven-file source draft remains frozen until the plan adopts or replaces it. The owner has directed full development. The implementation plan follows this refreshed design against engine 0.14.0.

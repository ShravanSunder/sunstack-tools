Program Design · One Rust engine, multiple consumers

The SDK is an additional host adapter over the existing Rust engine. The structural change is to separate definition acquisition from definition admission and execution. File loading and typed in-memory values meet at one immutable definition bundle; the engine keeps deciding validity, policy, requests and outcomes.

Who owns what

The native layer owns neither policy nor a second model engine. The CLI retains formatting and process signals. The engine facade supplies call-local execution and existing credential/backend services; the SDK does not install signal handlers, mutate global CWD, or return credentials to the script.

Root and origin call-path changes

CLI root derivation is preserved: invocation CWD → config discovery; config directory → Git workdir/fallback target root; invocation CWD → explicit paths. SDK adds a separate root argument → exact canonical checked root and root argument → explicit paths. Definition base remains separate on both paths. Both feed existing select_targets_in_root and existing scope/filter discovery. No global CWD mutation is used.

Changed definition-location edges are RulebookSentence.rulebook, InlineRule.origin and LintInvalid.file (plus report definition references). Shared content-based admission carries DefinitionOrigin at those edges. For unchanged file-based CLI calls, the CLI adapter projects real file origins back to the existing PathBuf fields and current LintReport serialization. The SDK projection keeps file/inline/edited variants. Checked-target Finding.file, PieceLocation and source spans remain actual target file locations. CLI does not consume inline SDK inputs, so no fictional physical path is needed.

The input and result shapes

All of these are Rust DTOs with generated TS declarations, not a hand-maintained implementation schema. Rust loads each source once, normalizes it into editable captured values, then the SDK deep-copies/freezes the result. load derives configuration.id from the canonical root config path; an authored configuration supplies its own nonempty ID. Configuration is the sole execution authority, including when passed inside LoadedConfiguration. CapturedValue.original is only provenance: the native capture owner parses it with its original source format and compares its normalized value with value. Equal values retain original content/origin; different valid values execute value and receive an edited origin, canonical content and recomputed digest. A malformed original is invalid; a stale supplied sha256 is never used. CapturedSource names the exact original decoder and, for a multi-rule YAML document, its definition_id. Missing/ambiguous IDs or a source format incompatible with the captured value return capture_metadata_invalid. No file extension guess decides the decoder. original_config contains root metadata/settings; referenced rule/matcher sources have their own captured records. No public filesystem-shaped adapter, opaque-only handle, definition cache or trust registry is needed.

The root source is compared after normalizing legacy RulesConfig settings to the SDK settings, excluding acquisition-only fields and expanding definition references from the captured records. Changed root settings, filters or kinds create an edited root snapshot; unchanged settings retain the original root bytes. Per-definition source records still identify their own changes. Copying configuration therefore preserves editable snapshots and resolution context while sources remains a historical load receipt. User-supplied provenance describes supplied content; acquisition never falsely claims the call read that file.

Every SDK report reuses current Rust result/finding/request/usage data without recalculating verdicts. CompletedReport narrows status to clean/nothing_selected/findings/uncertain; InvalidReport, IncompleteReport and CancelledReport narrow to their matching status. The shared Rust projection refuses prepared in ordinary SDK run. Before a report exists, the corresponding outcome explicitly carries no report. SdkReport retains all LintReport semantic fields: version, scope, status, findings, results, uncertain, selections, file_counts, skipped_rules, counts, exclusions, incomplete, usage, evidence_seen, limits, diagnostics, requests, filter_answers, filter_skips, piece_evidence and evidence_listing. Definition-specific config/rulebook references become origin-aware SDK fields; preparation remains absent in ordinary run. sources replaces physical-file-only rulebook_files. Exact requested/resolved models remain in canonical request/usage records. The CLI keeps the current serializer and field names.

LintInvalidCode is generated from the existing closed Rust enum (including credential_missing, backend_missing, no_git_for_default_scope and path_not_found). Source/adapter codes above are closed Rust variants, not arbitrary strings. Runtime/language labels and human messages do not substitute for codes. SdkFailure and all call outcomes are the exact Specification unions. The loader owns unsupported-runtime/platform and missing-addon classification before dispatch. The wrapper compares exact SDK release and contract revision, and verifies target selection before invoking the facade.

Ast-grep: precise types without a fork

Sunstack-owned DTOs use Specta derives. The upstream SerializableRuleConfig<SupportLang> schema cannot be derived directly: SupportLang has no JsonSchema implementation at 0.51.0. Generate nested rule, constraint, utility, transform, fixer, rewriter, label and glob declarations from the exact pinned upstream schema-bearing types, starting with SerializableRuleCore. A Sunstack Rust transport DTO composes that core with the full accepted wrapper property set in the Specification and a Rust-owned canonical upstream language-name DTO, distinct from the result EvidenceLanguage snake_case union. This small wrapper is necessary for the external generic language boundary; it converts into the real upstream config and never implements pattern policy.

The adapter parity gate enumerates wrapper fields/defaults against upstream SerializableRuleConfig, so omission of fix/rewriters/reporting/metadata fields cannot silently narrow compatibility. Generic upstream helper types that lack a usable schema get a Rust transport wrapper at that same edge, not a fork or TS handwritten duplicate. JSON-representable metadata has a recursive JsonValue type; unsupported YAML-only values are diagnosed explicitly by SDK acquisition without changing CLI decoding. Unknown wrapper-level properties retain upstream ignore behavior; unknown properties within rule and contextual-pattern objects retain upstream refusal. The adapter never strips nested fields to make them valid. TS object-literal checking and strict Sunstack refusal stay in place.

The upstream Rule<M> is prior art for optional grammar ergonomics, not a substitute for the full Rust config. Current grammar-map generation lists JavaScript/TypeScript/TSX/HTML/CSS; these are separate from the engine’s broader supported-language union; no unsupported static kind completeness is claimed. Pinned map list. Rust still compiles patterns, references, reserved utilities and languages. No duplicate parser execution, AST traversal API or codemod executor is added.

Integration against engine 0.12.1

The source base is a18bab3d (0.12.1). SDK root is absolute; relative input is refused before filesystem acquisition without consulting process CWD. Canonicalization never widens it to a Git parent. Generate concrete new language/field/anchor/mechanical-tool variants from current Rust contracts; preserve ClosedFileSource resolution Result semantics. Reuse explicit root handling already implemented in select_targets; do not add another root resolver. Preserve required ContextCapture choices at every existing ChangeCaptureRequest construction. The old seven-file DefinitionSource draft is not cherry-picked: content-based acquisition is implemented at current owners after inspecting their changes.

Load, check and run

The facade is a new library entry in the existing sunstack package rather than a new service. It exposes the existing credential/backend resolver only through effectful host operations; secrets stay inside Rust. CLI process signals remain the executable's responsibility; SDK cancellation is passed explicitly. Lower domain crates do not depend on NAPI or Node, and no library calls a binary that loops back into itself.

Cancellation, overlap and failure

An already-aborted signal wins before encoding/native dispatch and returns cancelled. A cancellation observed before execution starts prevents new work; a cancellation during execution cancels only that call and awaits owned settlement. Partial reports retain only actual work. Each call has its own explicit checked-root/definition-base paths, cancellation token, limits and backend context. Concurrent calls never change process CWD or overwrite shared environment to select a model/key. Any shared backend scheduler follows existing Rust request/concurrency limits rather than a second SDK queue.

Packaging and compatibility

Build compiled SDK code plus declarations and a small generated native loader. Use platform-specific optional native packages for Mac arm64/x64 and Linux arm64/x64 glibc/musl. Pin all artifacts to the same SDK release and expose a native contract-revision handshake before effects. Maintain Node 26 as the initial documented SDK runtime; the existing CLI package keeps its own runtime floor. The user writes TypeScript; generated package execution code is an implementation artifact.

CLI install/release channels, its binary and its reports remain unchanged. The native addon is a separate artifact and cannot inherit portability proof from the static CLI archive. Public registry publication, signing/notarization release policy and production deployment are separate delivery gates, not established by these design pages.

Enforcement and excluded machinery

Closed data variants and generated types constrain representable shapes. Trusted Rust admission rejects invalid refinements, markers, references, patterns and languages; the encoder rejects non-data inputs and unsafe numeric encoding. The native version guard rejects incompatible contracts. Tests observe these boundaries; they do not replace them. No database, run registry, remote worker, new credential store, durable cache, implicit retry layer or extra parser execution is needed.

The source-acquisition trait draft remains frozen pending implementation planning. It may be replaced by typed content acquisition, because a public definition object should not have to imitate directories or YAML files. Existing files remain an acquisition format and the CLI must retain its behavior. No implementation steps, commits or acceptance claims are prescribed by this structural design.

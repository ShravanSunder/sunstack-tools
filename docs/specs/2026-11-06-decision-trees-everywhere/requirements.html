Requirements: what you asked for

Every time sunstack asks Jev to judge something, it should ask a small tree of simple questions. That covers deciding which skills a rule reads, and deciding whether a rule warns. Examples belong in the rule files, and sunstack hands them to Jev. A rule proves itself on real cases inside sunstack. Then any agent that runs sunstack lint gets short warnings that point at files and lines.

I grouped what you asked for into the five parts below. You haven't named these parts yourself. If you'd split them differently, say so and the rows move. No row text changes.

Who this is for

  • Agents running sunstack lint on skills, in this repo or any other. They need warnings they can act on without flooding their context.
  • Rule authors: whoever writes a rulebook, in any repository. They need to build a rule as a tree, give Jev examples, and prove the rule without writing their own test tooling.
  • You, the owner. You need rules that work, so the work can move on to usable skills and the next parts.

What goes wrong today

  • The kind filter is one big five-way question. Its options each pack several conditions, and sunstack can't make a filter a tree at all.
  • The product-workflow rule's first question asks three things at once. Its examples are pasted into the question wording.
  • A week was spent rewording questions to move scores, not designing them.
  • Proof lived in a separate tool in this repo that hid every judged rule, so no agent got a single judged warning.

What this design won't do

  • No rewording rounds to push scores. Questions change only when the standard says their shape is wrong.
  • No test or adoption tooling in the ai-tools wrapper. Whatever proof is needed lives in sunstack. The current gate is removed.
  • No new rules. The kind filter and the product-workflow rule are rebuilt first. The other eight judged rules stay off and are rebuilt the same way afterwards, one at a time.
  • No pressure tests or behavior replays, except the two real review-skill evals U12 already allows.

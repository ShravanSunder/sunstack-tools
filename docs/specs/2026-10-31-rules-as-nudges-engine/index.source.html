Rules as nudges: the engine

The engine half of the accepted "rules as nudges" design. sunstack lint 0.6.0 tells the agent running a rule what it saw, on which line, how it was decided, and where else to read; and it checks JSON files, so the rule files themselves get rules. Every change is additive: a field a report carries today keeps its name and meaning, warn stays the nudge, and the engine still knows nothing about skills.

One nudge, before and after

Line 17 of ops-observability-stack/SKILL.md, the placement rule's nudge on the signed 0.5.0 engine and in the design.

Today's finding already carries its answers and path. What it lacks is the line inside the section, an explicit basis, the answers behind passes and drops, and the places to read: the standard that makes this a concern and the file the section loads. A place the run never read never appears as a link.

Three changes sit behind the report rather than in it: a section's loads are the loads in its own text, not its child sections' (U6); a rule can ask for the full enclosing section or a loaded file's fields (U7, sequenced last because no accepted rule needs it yet); and lint reads JSON evidence with every existing field source except yaml, which --check refuses on a JSON kind (U8). Severity, status and exit codes don't change, and a finding's existing span keeps its meaning (U9, U10).

Where each change lands

Blue is sunstack-evidence, amber is sunstack-rules, teal is sunstack-lint. Each change is an addition to the part that already owns it. The decision walk owns what a result is and how it was reached; piece building owns what a piece holds; the report projection owns what readers see. A locator is written on a finding route and sent as an ordinary Choice question built for each piece, so the decision crate doesn't change.

Line 17's path through the engine

Still one request per piece: the locator rides along with the rule's own questions, and only on requests the walk already needs. A low-confidence pick, a field longer than the locate limit, or an all-mechanical path keeps today's line and says default. A reply that picks a line it wasn't offered is refused like any malformed answer, so that piece shows as incomplete.

How each need will be proven

A plan; nothing has run yet. Two existing journeys are extended, the plan writes focused tests, and one keyed check runs once.

The first independent review found one blocker and ten other gaps; the four documents are corrected and its recheck is next. After it, Gate 1 accepts both designs at named revisions. Whether Jev picks the right line across many skills is for the placement rule's labelled cases in the skills pull request, not this engine change.

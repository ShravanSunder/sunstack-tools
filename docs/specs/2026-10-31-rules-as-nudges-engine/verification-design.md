## Shared observations

- **S1. Rulebook-lint journey, `--case nudge`** (existing journey extended, lasting). [`rulebook-lint.md`](../../../.agents/skills/verify-sunstack-rule/references/rulebook-lint.md) and its driver `scripts/verify/sunstack-rule/rulebook/rulebook-lint.ts` already drive the real `sunstack lint` binary at a declared commit and hash over a pinned fixture tree, replacing only model answers with scripted loopback replies, and read the report. The new case mode, added the way `--case selection` was, runs a nudge fixture (a rulebook with related fields, a locate question, a model gate, a judged pass, an over-cap body, a JSON rules file) with `--format json` and `--format sarif`, and reads `findings[].related`, `.anchor`, `.basis`, `results[]` (`basis`, `path`, `answers`, `cut`) and SARIF `relatedLocations`. Expected values come from the Specification's sample report and the fixture's own files, not from the build.
- **S2. Check-refusal journey, extended** (existing: [`rulebook-check-refusals.md`](../../../.agents/skills/verify-sunstack-rule/references/rulebook-check-refusals.md), lasting). Adds refusals for `related` naming an unknown field, `locate` naming a question that isn't a locate question, and `yaml` on a JSON kind; reads each diagnostic's file, entry path and field, and exit 2.
- **S3. Focused crate tests** (no journey; the plan writes them). The decision walk with fixed answers (answers read, basis, anchor), piece building (own text, full text, path fields, opening cut), the evidence project's JSON parsing, and the report schema. The process test [`rulebook_lint_process.rs`](../../../crates/sunstack/tests/rulebook_lint_process.rs) already runs the real binary against `controlled::ControlledServer` and asserts the exact `results[]` rows; its expected rows gain the new fields from the Specification's sample report. That is a deliberate contract change, not a weakened check.
- **S4. Keyed line-17 check** (needed, temporary). One run of the release build with the real decision model over the frozen line-17 piece (the `spike-1` copies in the owner's memory-logs) and a placement fixture rule with a locate question; reads the finding's line and `anchor`. The Lead holds the key; the driver never prints it and checks its output for it; the run is deleted after its evidence is kept.

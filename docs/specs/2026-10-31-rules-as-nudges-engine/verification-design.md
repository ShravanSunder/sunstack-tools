## Shared observations

- **S1. Rulebook-lint journey, `--case nudge`** (existing journey extended, lasting). [`rulebook-lint.md`](../../../.agents/skills/verify-sunstack-rule/references/rulebook-lint.md) and its driver `scripts/verify/sunstack-rule/rulebook/rulebook-lint.ts` already drive the real `sunstack lint` binary at a declared commit and hash over a pinned fixture tree, replacing only model answers with scripted loopback replies, and read the report and the exact request bodies. The new case mode, added the way `--case selection` was, runs a nudge fixture (related fields; a located route; a model gate; a judged pass; a judged gate then an unavailable mechanical field; an over-cap body beside an authored `cut` field; a JSON rules file) with `--format json` and `--format sarif`. It reads `findings[].related`, `.anchor`, `.basis`, `.line`, `.span`, `results[]` (`basis`, `path`, `answers`, `cut`), `evidence_seen`, SARIF `relatedLocations` and regions, and each request body's questions and state. Expected values come from the Specification's sample report and the fixture's own files, never from the build.
- **S2. Check-refusal journey, extended** (existing: [`rulebook-check-refusals.md`](../../../.agents/skills/verify-sunstack-rule/references/rulebook-check-refusals.md), lasting). Adds refusals for `related` naming an unknown field; a locator without `at`, with a name equal to a question's or another locator's, or with `min_probability` outside (0, 1]; `exclude: { "kind": ... }` on a target field; `yaml` on a JSON kind; and a JSON kind's `inside` field naming a Markdown rule. Each reads the diagnostic's file, entry or kind, and field, and exit 2. It also accepts, with exit 0, a JSON kind with one field of every admitted source.
- **S3. Focused crate tests** (no journey; the plan writes them). The decision walk with fixed answers (answers read, basis, anchor, incomplete history), the rulebook run's request construction (which locators it sends and their labels), piece building (own text in both scans, full text, path fields, opening cut and last line), the evidence project's JSON parsing, admission, and the report schema. Formatter tests call the real `render` (`crates/sunstack-lint/src/lint_reporting/formats.rs`) for `Default` and `Github` on a contract report whose finding has `line: 17`, `anchor: "resolved"` and a `span` starting at line 7, and assert the finding's own printed location is 17 (not a related place's line); a control report with `anchor: "default"` prints 7, as today. Existing CLI format tests keep covering format dispatch. The process test [`rulebook_lint_process.rs`](../../../crates/sunstack/tests/rulebook_lint_process.rs) already runs the real binary against `controlled::ControlledServer` and asserts the exact `results[]` rows. Its expected rows gain the new fields from the Specification's sample report, and it gains judged pass and judged drop cases. Changing expected keys alone wouldn't prove them.
- **S4. Keyed line-17 check** (needed, temporary). One run of the release build with the real decision model over the frozen line-17 piece (the `spike-1` copies in the owner's memory-logs) and a placement fixture rule whose finding route has a locator; reads the finding's line and `anchor`. The Lead holds the key; the driver never prints it and checks its output for it; the run is deleted after its evidence is kept.

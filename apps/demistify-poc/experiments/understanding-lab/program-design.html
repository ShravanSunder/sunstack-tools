Program Design

Start with what the person needs to do. Read the authored needs here, then follow the specification, design and verification pages for their supporting details.

These six needs and their pass/fail observations are examples for comparing the interface. They are not assertions about the current picker or another shipped product.

C1 · Input scope routing

InputOwner routes the event; DialogScope resolves the target.

Opening a dialog pushes its scope. A key enters handleKey; InputOwner.route reads the top scope and forwards to DialogScope.resolve. Closing removes that scope before later input is routed.

Component responsibilities
Component Responsibility
InputOwner Owns the scope stack and chooses its top entry.
DialogScope Resolves only the chosen dialog’s local bindings.
Refusal and recovery

If the top scope has no matching binding, the event remains blocked from lower scopes.

Pointer entry, menu ownership and the enforcing component are not described. An observable action effect and completion signal are also missing.

Missing paths and proof seams
  • S2's pointer case needs an entry path and an explanation of how lower-scope session actions stay inactive while the menu is modal.
  • S2's menu input ownership is not described; C1 only explains dialog scopes.
  • The component enforcing the stated no-fallback outcome is not named.
  • Proving S2 needs an observable background-action effect and a completion signal for the attempted input.

C2 · Action registration

ActionRegistry owns the action and its shortcut.

Shortcut lookup resolves an action ID. Invocation uses that same entry; Help reads its label and key without a second shortcut map.

Component responsibilities
Component Responsibility
ActionRegistry Keeps the action label, shortcut and callable together.
HelpPanel Reads the registered entry when showing help.
Refusal and recovery

An unregistered key has no callable action. Help must not advertise an invented binding.

C3 · Local selection

SelectList owns local navigation and commit.

Arrow keys update the active index within the available options. Enter reads that index and returns the selected machine; movement alone does not commit.

Component responsibilities
Component Responsibility
SelectList Retains the active option index.
Machine chooser Receives only the option committed by Enter.
Refusal and recovery

With no available option, Enter has nothing to commit.

C4 · Overlay composition

OverlayHost owns layering and the opaque frame.

Responsibilities and components
Component Responsibility
OverlayHost Allocates the overlay bounds above the background.
Dialog frame Paints the full opaque area, including its left edge.
State, flow and boundary

Opening mounts the dialog into the overlay layer. Bounds and inset reserve the entire frame before text is painted, so a wide background glyph cannot cross its edge.

Refusal and recovery

If the available width cannot fit the content, keep it within the overlay bounds rather than exposing the background.

C5 · Session start result

StartSession owns its result; the dialog retains the draft.

Responsibilities and components
Component Responsibility
StartSession Returns either a started session or a refusal reason.
Session dialog Keeps the draft until a started result is received.
State, flow and boundary

Submit reads the existing draft and calls StartSession.run. A started result closes the dialog. A refused result displays the reason beside the unchanged draft.

Refusal and recovery

A refusal leaves the entered machine and title available for retry. Retrying submits the retained draft.

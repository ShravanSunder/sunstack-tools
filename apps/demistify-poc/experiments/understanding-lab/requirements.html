Start from the user need

Start with what the person needs to do. Read the authored needs here, then follow the specification, design and verification pages for their supporting details.

These six needs and their pass/fail observations are examples for comparing the interface. They are not assertions about the current picker or another shipped product.

U1 · Type into the active surface

When I open a dialog, my typing belongs to that dialog.

U2 · Keep background actions inactive

An open menu must not trigger a session action behind it.

U3 · Find the command and its real key

Help should show the key that actually runs each command.

U4 · Navigate every choice by keyboard

I can choose a machine without switching to the mouse.

U5 · Read the whole dialog cleanly

Text behind a dialog must not leak through its frame.

U6 · Keep the draft when a request fails

If starting a session fails, keep what I entered so I can retry.

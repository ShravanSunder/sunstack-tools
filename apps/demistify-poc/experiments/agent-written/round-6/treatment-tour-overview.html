# Notification service overview Illustrative service, dated 2026-10-14. For engineers joining the notifications team. The [delivery queue deep dive](treatment-tour-queue.html) covers message states, the retry policy and change #341. Start with the summary of the service. Follow the flow of parts from event intake to channel workers. On the deep dive: the message states. On the deep dive: the retry change under review. Back on the overview: the proposed digest batcher. ## Summary The notification service turns product events into emails, push messages and SMS. It accepts about 2.1 million events a day and delivers 99.4% within one minute. ## Parts and flow Receives product events from the event bus. Validates them and de-duplicates them by event id. Turns an event and a template into a message per channel. Each user's channels, quiet hours and unsubscribes. Groups low-priority messages into one daily email per user. Sits between the Composer and the Delivery queue. Holds messages until a channel worker sends them, and retries failures. See the [deep dive](treatment-tour-queue.html). Email via a mail provider, push via the mobile push services, SMS via an SMS gateway. Approved in design review on 2026-10-10. Implementation not started.

# Notification service overview The notification service turns product events into emails, push messages and SMS. It accepts about 2.1 million events a day and delivers 99.4% within one minute. ## Parts and flow Five parts take a product event to a channel. The composer reads the preference store. The digest batcher is a proposal: the proposed switch at the top hides it and shows the current system. Receives product events from the event bus. Validates them and de-duplicates them by event id. Turns an event and a template into a message per channel. Holds messages until a channel worker sends them. Retries failures. [Deep dive](control-tour-queue.html) One per channel: email through a mail provider, push through the mobile push services, SMS through an SMS gateway. Each user's channels, quiet hours and unsubscribes. Postgres. Groups low-priority messages into one daily email per user. Approved in design review on 2026-10-10. Implementation has not started.

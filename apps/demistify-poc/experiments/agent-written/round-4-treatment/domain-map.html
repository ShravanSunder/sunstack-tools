# Commerce domain map Five areas own twenty entities. This is the one place to see every entity, where it lives and how entities connect. Illustrative domain, dated 2026-10-14. An order is the spine: identity places it, catalog prices it, billing pays for it, fulfilment delivers it. Start with the map: five areas around one spine. The order is the spine. Its lines copy prices at purchase, and payment and shipment hang off it. Ordering: carts become orders. Billing: money in and out. Fulfilment: getting it to the customer. ## The map
- Order line prices are copied at purchase; changing a Price never changes an existing order. - Inventory is reserved at checkout and released if payment fails within 15 minutes. - A cancelled order that was already paid needs a Refund; cancelling does not refund by itself.
## Areas and entities Person or company that places orders.
Fields and rules Fields: id, name, email, type (person | company), created at. **Rule:** email is unique.
Sign-in credentials for a customer.
Fields and rules Fields: customer id, password hash, MFA enabled, last sign-in. **Rule:** one account per customer.
Postal address, used for shipping and invoices.
Fields and rules Fields: lines, city, postcode, country.
Marketing and data-processing consents.
Fields and rules Fields: customer id, purpose, granted at, version. **Rule:** append-only; latest version wins.
A sellable item family.
Fields and rules Fields: id, name, description, status (draft | live | retired).
A specific size or colour.
Fields and rules Fields: sku, product id, attributes, weight.
Price of a SKU in a currency.
Fields and rules Fields: sku, currency, amount, valid from. **Rule:** one active price per SKU and currency.
Stock per SKU per warehouse.
Fields and rules Fields: sku, warehouse id, on hand, reserved.
Items before checkout.
Fields and rules Fields: id, customer id (optional), lines, expires at. **Rule:** expires after 7 days idle.
The committed purchase.
Fields and rules Fields: id, customer id, status, totals, placed at. **States:** placed → paid → fulfilled → closed; cancelled from placed or paid.
One SKU in an order.
Fields and rules Fields: sku, quantity, unit price at purchase. **Rule:** price is copied, never re-read.
A promotion applied to an order.
Fields and rules Fields: code, amount or percent. **Rule:** at most one per order.
An attempt to collect money.
Fields and rules Fields: id, order id, method, amount, status (authorised | captured | failed | refunded).
Legal document issued when an order is paid.
Fields and rules Fields: number, order id, billing address, tax lines. **Rule:** numbers are sequential per country.
Money returned.
Fields and rules Fields: payment id, amount, reason. **Rule:** total refunds ≤ captured amount.
Rate by country and product class.
Fields and rules Fields: country, class, percent.
A stocking location.
Fields and rules Fields: id, address, cut-off time.
Goods leaving one warehouse for one order.
Fields and rules Fields: id, order id, warehouse id, status (pending | packed | shipped | delivered).
A physical box in a shipment.
Fields and rules Fields: tracking number, carrier, weight.
Goods coming back.
Fields and rules Fields: order line, reason, received at. **Triggers:** a refund.
## Relationships - Customer → Account (has one) - Customer → Address (has many) - Customer → Order (places) - Cart → Order (checks out to) - Order → Order line (contains) - Order line → Variant / SKU (refers to) - Variant / SKU → Product (belongs to) - Variant / SKU → Price (priced by) - Variant / SKU → Inventory level (stocked as) - Order → Payment (paid by) - Payment → Invoice (issues) - Payment → Refund (reversed by) - Order → Shipment (fulfilled by) - Shipment → Warehouse (leaves from) - Shipment → Parcel (contains) - Return → Refund (triggers) ## Open questions Address is a value today. Should it become an entity with an id so invoices can reference it after edits? Do company customers need multiple accounts? Today the rule is one account per customer.

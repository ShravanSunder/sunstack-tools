# Commerce domain map Illustrative domain, dated 2026-10-14. An engineer joining the team uses this page to see every entity, where it lives and how entities connect. Open an area to look up an entity's fields and rules. An order is the spine: identity places it, catalog prices it, billing pays for it, fulfilment delivers it. ## Quick tour Identity places it: a customer, a person or a company, places the order. Catalog prices it: each SKU has one active price per currency. The order is the spine. It moves from placed to paid, fulfilled and closed, and can be cancelled from placed or paid. Billing pays for it: a payment collects money, and an invoice is issued when the order is paid. Fulfilment delivers it: a shipment leaves one warehouse for one order and contains parcels. ## Areas and entities Customer, Account, Address and Consent record. A customer has one account and many addresses. Person or company that places orders. **Fields:** id, name, email, type (person or company), created at. **Rule:** email is unique. Sign-in credentials for a customer. **Fields:** customer id, password hash, MFA enabled, last sign-in. **Rule:** one account per customer. Postal address, used for shipping and invoices. **Fields:** lines, city, postcode, country. Marketing and data-processing consents. **Fields:** customer id, purpose, granted at, version. **Rule:** append-only; latest version wins. Product, Variant / SKU, Price and Inventory level. The catalog prices what an order contains. A sellable item family. **Fields:** id, name, description, status (draft, live or retired). A specific size or colour. **Fields:** sku, product id, attributes, weight. Price of a SKU in a currency. **Fields:** sku, currency, amount, valid from. **Rule:** one active price per SKU and currency. Stock per SKU per warehouse. **Fields:** sku, warehouse id, on hand, reserved. Cart, Order, Order line and Discount. A cart checks out to an order. Items before checkout. **Fields:** id, customer id (optional), lines, expires at. **Rule:** expires after 7 days idle. The committed purchase. **Fields:** id, customer id, status, totals, placed at. **States:** placed → paid → fulfilled → closed; cancelled from placed or paid. One SKU in an order. **Fields:** sku, quantity, unit price at purchase. **Rule:** price is copied, never re-read. A promotion applied to an order. **Fields:** code, amount or percent. **Rule:** at most one per order. Payment, Invoice, Refund and Tax rate. An attempt to collect money. **Fields:** id, order id, method, amount, status (authorised, captured, failed or refunded). Legal document issued when an order is paid. **Fields:** number, order id, billing address, tax lines. **Rule:** numbers are sequential per country. Money returned. **Fields:** payment id, amount, reason. **Rule:** total refunds are at most the captured amount. Rate by country and product class. **Fields:** country, class, percent. Warehouse, Shipment, Parcel and Return. A stocking location. **Fields:** id, address, cut-off time. Goods leaving one warehouse for one order. **Fields:** id, order id, warehouse id, status (pending, packed, shipped or delivered). A physical box in a shipment. **Fields:** tracking number, carrier, weight. Goods coming back. **Fields:** order line, reason, received at. **Triggers:** a refund. ## How the entities connect
- Order line prices are copied at purchase; changing a Price never changes an existing order. - Inventory is reserved at checkout and released if payment fails within 15 minutes. - A cancelled order that was already paid needs a Refund; cancelling does not refund by itself.
Consent record, Discount and Tax rate have no relationship, so the diagram leaves them out. ## Relationships - Customer → Account (has one) - Customer → Address (has many) - Customer → Order (places) - Cart → Order (checks out to) - Order → Order line (contains) - Order line → Variant / SKU (refers to) - Variant / SKU → Product (belongs to) - Variant / SKU → Price (priced by) - Variant / SKU → Inventory level (stocked as) - Order → Payment (paid by) - Payment → Invoice (issues) - Payment → Refund (reversed by) - Order → Shipment (fulfilled by) - Shipment → Warehouse (leaves from) - Shipment → Parcel (contains) - Return → Refund (triggers) ## Order lifecycle ## Status values | Entity | Status values | | --- | --- | | Order | placed, paid, fulfilled, closed, cancelled | | Payment | authorised, captured, failed, refunded | | Shipment | pending, packed, shipped, delivered | | Product | draft, live, retired | ## Open questions - Should Address become an entity with an id so invoices can reference it after edits? - Do company customers need multiple accounts?
